1. ❌ → ✅ VBS Launcher Hardcoded Username Bug

2. ❌ → ✅ Web Server HTTP Listener Crash Bug
   ──────────────────────────────────────────
   FILE: phantom-activity-webserver.ps1
   
   PROBLEM:
   - .GetContext() blocking call caused:
     * "Access Denied" errors (shown in logs)
     * Server crashes on port conflicts
     * No error recovery mechanism
     * Repeated error spam (100+ errors in single second)
   - Root cause: Synchronous blocking pattern
   
   SOLUTION:
   - Implemented BeginGetContext/EndGetContext async pattern
   - Added 5-second timeout to prevent permanent blocking
   - Wrapped listener.Start() in proper try-catch
   - Added error detection for admin privilege requirement
   - Now gracefully handles port conflicts
   
   IMPACT:
   - Server stays online and recovers from errors
   - No more cascading error spam
   - Better diagnostics for admin privilege issues
   

3. ❌ → ✅ File Encoding & Log Lock Contention
   ────────────────────────────────────────────
   FILE: vscode-cycle.log
   
   PROBLEM:
   - Log file had Windows-1252 encoding (legacy)
   - Multiple processes writing simultaneously caused locks
   - Write-Log function had no retry mechanism
   - Unable to read/modify file with UTF-8 tools
   - Size: 1.8 MB of mostly error spam
   
   SOLUTION:
   - Deleted old malformed log file
   - Created fresh UTF-8 encoded log
   - Added retry mechanism in Write-Log (3 retries, 50ms wait)
   - Updated phantom-activity-webserver.ps1 with same retry logic
   - Now handles concurrent writes gracefully
   
   FILES MODIFIED:
   - phantom-activity-webserver.ps1: Get-RecentLogs, Write-Log
   

4. ❌ → ✅ Web Server Error Handling & Response Closing
   ───────────────────────────────────────────────────
   FILE: phantom-activity-webserver.ps1 (Invoke-HttpResponse function)
   
   PROBLEM:
   - No try-catch in response handler
   - Response stream not properly closed on errors
   - Unhandled exceptions could leave stream hanging
   - Browser clients getting partial/malformed responses
   
   SOLUTION:
   - Wrapped entire response handling in try-catch
   - Added explicit error logging for HTTP responses
   - Ensured stream.Close() is always called
   - Added fallback HTML response when file not found
   - Better error messages for diagnostics
